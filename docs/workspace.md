# 项目工作区

Workbench 是应用唯一的布局，在一个窗口内提供左右两个工作面板。每侧使用现有的工作台和 Tab 组件，顶部通过加号菜单打开「更改 / 文件 / 新对话」。打开的页面与文件、具体对话一样可关闭、可重排；加号菜单每次为文件或更改页面创建独立实例，新对话每次创建独立草稿；同侧也可并存多个同类页面。已有文件或会话的导航入口继续复用其身份。

没有打开内容时，每侧显示「开始」fallback 标签和页面，提供「新对话 / 文件 / 更改」入口，与加号菜单共用面板专属操作。打开内容后开始页自动让位，关闭最后一个 Tab 后恢复。开始页仅由空状态派生，不写入面板或文档 Store，不可关闭或重排；有内容时不会作为固定标签保留。

对话暂时只基于窗口当前选中的项目。两侧目录复用 `AgentSessionTree` 的当前项目会话列表，包含相同的 Agent 图标、相对时间、活动状态、重命名和删除菜单，不显示其他项目或独立对话。列表点击在来源面板打开项目会话 Tab。加号、开始页、目录和快捷键创建当前项目的会话；未选项目时先打开全局项目选择器，不创建独立工作目录。左上角、新对话欢迎语中的项目名、输入框上方的项目栏共用全局项目菜单与切换回调；三个入口效果一致，切换整个窗口并恢复目标项目布局，不修改单个对话的 CWD，也不额外创建会话。

每个项目按稳定的 Project ID 保存自己的双栏工作区。切换项目会恢复该项目的全部 Tab、排列顺序、选中项、目录开关与分段、焦点和分屏比例。已访问项目的对话组件保留挂载，未发送内容与附件在往返切换后仍在；后台会话物化写回所属项目。文件内容由共享缓冲区保留，切换项目不丢弃未保存编辑。旧独立对话及原始布局保留在历史存储中，不展示、不挂载运行时。

## 布局与平台

- 两侧 Tab Header 与窗口控件位于同一顶行，不再添加单独的空白标题栏。分隔线与面板内容边界对齐。
- 左侧 Header 依次为工作目录下拉框、左侧目录入口，兼顾 macOS 非全屏交通灯区域；右侧依次为右侧目录入口、搜索、设置以及 Windows 窗口按钮预留横向空间。搜索与设置间隔 2px。
- 工作目录下拉框复用 AppMenu.TriggerSurface 和项目菜单，按触发按钮位置弹出。高度 32px、宽度随名称变化且最大 240px，窄面板进一步压缩并省略长名称；目录入口与 Tab 起点随控件实际宽度调整。
- 安全区域复用 `shell-layout.ts` 的平台变量，macOS 全屏释放交通灯区域。仅渲染一份全局标题栏。
- 顶部没有模式切换器或占位。Windows 工作目录下拉框从窗口左侧 6px 开始；目录按钮与首个 Tab、末个 Tab 与加号按钮继续保留 6px 间距。
- Tab 可交互区域使用 no-drag，空余 Tab 区域保留窗口拖动能力。系统窗口状态事件更新最大化按钮。
- 两侧默认等宽，可拖动分隔线调整；分隔线支持方向键、Home/End、Enter 和双击复位。每侧尽量保留 320px。
- 两侧独立提供「文件 / 更改 / 对话」目录侧栏，左侧在左缘展开，右侧在右缘展开。侧栏不依赖当前 Tab 类型或是否已连接工作目录；开关与分段选择互不影响，内容打开到所属面板。
- 目录始终占据布局空间，通过圆角和与 AppMenu 相同的阴影呈现浮层样式，不覆盖内容；目录与内容之间保留 6px 间距。窄面板下目录入口与移动箭头均保留，不因宽度不足 520px 隐藏移动功能。

## 状态与交互边界

- 布局恢复只复用文件/会话读取结果；「文件 / 更改」页面分别保存实例 ID 与面板类型，恢复后保留所有实例、顺序和选中项。旧布局中两侧共用固定 ID 的面板在恢复时分配独立身份，下次保存后保持稳定。切换、打开、关闭和跨栏移动都会推进本侧临时导航版本，已过期的读取不能重新选中页面；版本不写入持久化。
- 文档删除同步清理当前及已访问项目的面板引用。Git 刷新只处理当前仓库范围内的差异，并使用差异自身的仓库根路径查询。保存完成只推进已保存基线，保留等待期间产生的编辑或撤销，包括另一侧同文件视图的内容。
- 全局菜单和设置接收当前可见对话的运行时状态，优先使用焦点所在侧；保留挂载的后台对话不覆盖此状态。独立对话的历史格式仍可读取和迁移，不保留已经没有调用方的创建/物化入口。

- `workbench-state.ts` 保存当前项目布局、已访问项目的内存布局，以及尚未访问项目的持久化引用。文件内容继续由 Workspace Store 管理，同一文件跨面板、跨项目打开时共享编辑缓冲区。
- 每侧分别管理激活 Tab 和目录展开状态，目录树内部的分支展开仍为面板内临时状态。文件浏览和 Git 历史视图属于各自 Tab，随 Tab 移动。关闭共享文件的一个引用不关闭其他面板或已访问项目中的引用；关闭最后一个引用沿用原有保存与关闭流程。
- 移动箭头位于各个可移动 Tab 内、关闭按钮前方，提示为「移到右侧 / 移到左侧」：一次更新将所点击的文件、差异、对话或「文件 / 更改」页面移至另一侧并聚焦，未选中的 Tab 也可直接移动；目标侧已有相同 Tab 时保留其顺序并激活，不新增副本。来源侧按关闭规则选择相邻 Tab，移走最后一个后显示「开始」。移动仅转移本项目的面板引用，不关闭共享文档、不触发保存确认，保留未保存内容、差异版本及 Markdown/代码/普通文本差异的选区和滚动位置；旧异步打开请求不能抢回焦点。移动结果沿用项目布局持久化；两侧目录的开关和分段选中项不随 Tab 移动。「开始」由空状态派生，不提供移动操作。
- 对话、文件、更改列表统一使用 AppItem 方向按钮：单击条目在本面板打开；悬停或键盘聚焦时，行尾现有操作之前显示「在右侧打开」或「在左侧打开」。方向按钮在目标面板打开并复用该侧已有标签，文件夹和重命名状态不显示。更改条目保持差异语义，包含已暂存、未暂存和历史提交文件；历史文件保留其提交版本。原有更多、重命名、暂存等操作保持不变。
- 可移动 Tab（包括「文件 / 更改」）随标题自然伸缩，最小宽度为 108px，不为隐藏的按钮组额外撑宽标题。选中和未选中的标签均在悬停或键盘聚焦时显示移动、关闭按钮；鼠标点击后移开不常显。两个 24px 按钮使用 16px 图标，保留 2px 间隔，前缘 16px 渐变覆盖标题尾部，显示前后标题和 Tab 宽度不变；被遮挡的标题提供完整文字提示。渐变沿用当前主题和激活状态的背景；未保存标记及拖动时的按钮隐藏规则保留。
- Tab 栏溢出时，激活 Tab 在原有位置正常排列，到视口边缘后通过原生 sticky 停住并保持完整可见；切换激活项不改变标签顺序。仍使用同一个 Base UI Scroll Area 浏览其他标签；前序标签在激活项之前、后序标签在其之后裁切，并且仅在被裁切处以 24px 透明度渐变淡出。激活项及其 SVG 轮廓、背景、阴影不做渐隐，轮廓直接读取实际显示位置。多个标签时按实际面板宽度限制长标题，空间允许时额外留出 108px 浏览相邻标签；该上限同时作用于所有标签，切换不会改变宽度。单个标签仍可充分使用栏宽，极窄空间不足 108px 时以可用空间为上限；调整窗口宽度后恢复自然宽度。拖拽插入提示与轮廓共用滚动测量；键盘导航直接使用稳定 Tab ID 和当前排列顺序，新增、关闭、跨栏移动和重排后均不依赖缓存索引，也不通过失焦再聚焦补偿。
- 同一对话只保留一个活动视图；普通列表点击再次打开时聚焦已有 Tab，显式方向按钮则把已有会话移至指定面板。项目、Agent 和会话路径共同标识已物化的对话，重新打开不会复制原先以草稿 ID 创建的标签。不同新草稿仍独立存在。
- `WorkbenchConversationLayer` 在双栏共同的 React 层级按稳定 Tab ID 挂载对话。每个 Portal 的目标容器固定，移动时仅将该 DOM 容器放入另一侧宿主，保持 AgentProvider、输入框和时间线实例；草稿、附件、模型选择及生成中的回复不因移动重置。容器移动后恢复选区、滚动和焦点，兼容不支持 `moveBefore` 的宿主。关闭确认、文件链接、新建对话及会话物化回写均跟随当前所属面板；创建会话期间也可移动，异步完成按稳定 Tab ID 查找当前所属项目及面板。关闭含未发送内容的对话仍会请求确认。
- `WorkbenchPanelLayer` 按项目和 Tab 实例保留文件浏览器、Git 面板的 Portal。同侧及两侧均可独立打开同类页面；移动只转移指定实例，目标侧已有同类 Tab 的顺序、状态不变，来源实例追加到目标侧并激活。目录位置、前进后退、视图、搜索、选择、Git 历史及滚动不会因移动重置，后续打开文件/差异的操作指向新的所属面板。访问过的实例在切换 Tab 或项目时隐藏，关闭时卸载；未访问的后台 Tab 按需挂载。布局归属写入项目持久化，组件内部的浏览状态只在当前窗口生命周期内保留。
- 目录中的对话列表复用 AgentProvider 的目录读取、事件订阅和行操作，使用 `workspaceActivation='none'`，不执行会话初始化、运行时刷新或会话选择持久化。否则它会与对话 Tab 竞争同一项目的原生激活，导致新对话初始化被取消。对话 Tab 保持完整运行时能力；初始化失败明确显示原因并支持保留草稿重试。
- 项目对话开始后保留 Tab ID，避免重挂载输入框；会话运行于对应项目目录，创建不会切换全局工作目录。
- 文件列表、目录树、对话文件链接、Git 差异均在触发操作的面板打开；列表的「在另一侧打开」和顶部的「移到另一侧」操作显式跨栏。对话链接携带该对话的工作目录。面板回调显式绑定来源侧；项目选择一发生便使旧文件请求失效，不等 CWD 更新后才失效。恢复未完成时禁止底层 Tab 操作，完成后的旧请求不能覆盖新项目。
- 项目恢复期间保留上一项目的双栏内容、标题和配置，目标项目准备好后一起切换。恢复状态仅用于请求隔离、阻止误操作和持久化，不隐藏工作区，也不显示全屏中间页；真实恢复错误使用局部提示。
- 保存较旧快照完成时不会覆盖较新的编辑草稿。重命名、删除和启动后恢复的文档会同步面板引用。
- 键盘关闭、切换 Tab、新建对话作用于焦点面板；模态对话框打开时屏蔽底层工作台快捷键。

## 生命周期

应用入口只挂载 `WorkspaceShell`，快捷键和搜索会话直接路由到当前面板。窗口状态由 `useWindowChrome` 管理；没有布局模式开关、模式 CSS 属性或 `layoutPreference` 配置。旧三栏外壳、抽屉控制器与模式专属固定标签逻辑已移除。

项目首次打开且没有已保存布局时，默认左侧目录展开，分段选中「对话」，并打开一个属于该项目的「新对话」Tab。右侧依次打开「文件」「更改」两个 Tab，选中「文件」；目录默认收起，分段选中「更改」。左右等宽、焦点在左侧。未选项目时新建对话入口引导选择项目。已有持久化布局（包括主动关闭全部 Tab 的空状态）优先恢复。

Workbench 布局通过现有 `AppStateStore` / `AtomicJsonStore` 写入 `layout.projectWorkspaces.layouts[projectId]`。变动合并写入，正常关闭窗口前等待最后一次写入完成；当前项目和后台已访问项目一起快照，未访问项目的记录原样保留。两侧全部关闭的空状态同样保留，「开始」仍由空状态派生。

首次迁移按项目会话的 Project ID、文件工作区或所属路径拆分旧 `layout.legacyWorkspaceLayout`，未归属的草稿绑定当时选中的项目。保留原始 `layout.legacyWorkspaceLayout` 作为迁移前存档；新映射一旦存在就不重复导入，防止已关闭的旧 Tab 再出现。项目显示名称可重复或修改，不影响归属。

重启时先恢复选中项目及其文件系统，再加载该项目的布局与文档；其他项目首次访问时才读取文件。Workbench 禁用旧的独立对话启动恢复及全局文件 Tab 恢复/写入，避免两套持久化相互覆盖。切换、添加和新建项目均保留共享文档缓冲区；切换失败时回到原项目。不可访问的根目录显示已有错误信息，保留已保存布局供重试。两侧共享文件只读取一次；失效文件会跳过，选中项回退到相邻可用 Tab。只保存引用，不复制文件内容、消息历史或未发送的输入/附件到布局 JSON。

每个对话 Tab 独立挂载共享 `AgentProvider`。历史快照读取的取消标记与导航去重标记必须一起清理：开发环境 StrictMode 重放挂载时，如果只取消请求却保留“目标已处理”的标记，替代请求会被跳过，`isSessionLoading` 将一直为真，同时禁用输入、发送、模型和附件。共享导航钩子在 layout effect 清理中同时失效旧请求、清空目标标记；保留共享会话的就绪检查。

工作区加载、打开及创建会话返回的是发起请求的 Tab 所需状态，不以项目的全局激活顺序取消其他 Tab 的请求，也不因此回滚其他 Tab 创建的会话。PI CLI、Codex 和 OpenCode 各自保留独立的请求结果，只有最新激活可以更新项目当前会话；工作区释放及运行时失效仍使请求失败。单个 Tab 内的过期请求继续由渲染器加载协调器及会话导航检查丢弃，较早请求的结果不通过全局事件抢占其他 Tab，加载成功后也会作废此前尚未完成的工作区广播快照。

主进程将旧 `layout.duoProjects` 读入 `layout.projectWorkspaces`，将更早的 `layout.duo` 读入仅用于迁移的 `layout.legacyWorkspaceLayout`；新数据优先，即使保存的项目集合为空也不会重新导入旧 Tab。新的写入不再携带旧模式偏好和全局侧栏尺寸。

Git 列表/树形偏好由 `useGitWorkspaceController` 直接保存，继续使用 `layout.gitPanelLayout`，不依赖窗口布局控制器。拖动双栏分隔线结束后，消息视口根据工作区的 `data-resizing` 恢复置底；正在阅读历史消息时保留阅读位置。
